# Full-course runtime generation

Level01 now has one procedural layout from the start to the 1,500 m finish. Scene assets are not rewritten.

- `ProceduralTrackStartup` snapshots authored objects once per scene load, before the builders run. It disables the opening forest, manual gameplay pickups/obstacles, intro bomb, trail-edge details, and stray opening water/decorative props. The small manual Gameplay tail past 220 m is also retired to prevent overlapping layouts. Cameras, directional light, runners, chaser, HUD, EventSystem, ground/road, managers, finish, and the existing river module remain intact.
- `RunnerCourseGenerator` overrides the old serialized 245 m boundary at runtime. Roadside chunks start at zero. The first 25 m contain no generated pickups or obstacle envelopes; bananas begin at 25 m. Existing safe-lane/reaction-distance rules generate the opening and the remainder of the course. Shield, Thunder and Magnet are placed on safe procedural rows before 220 m, with coconut and bomb pickup cadence alongside banana trails.
- `ProceduralTrackPool` stores placements rather than constructing the whole course. At 10 Hz it rents instances inside `[cameraZ - 15, maxRunnerZ + 110]`, registers each root with `TrackDistanceStreamer`, and prepares its materials/mobile shadows. Collected or passed placements retire permanently. A camera-only excursion can hide/return an instance without retiring an unpassed placement.
- Pool reuse explicitly resets collectible flags, child activity, child transforms, collider state and moving-hazard origin/travel. A consumed placement never respawns; an object can serve a different placement. Destroy-pending impact victims are not reused. Idle storage is capped at 12 instances per prefab.
- `TropicalScenery` provides pooled vegetation on both banks from Z=0, replacing the duplicate course-wide tree pass. It avoids both the original river gap and extension water spans. Bridge walking surfaces remain persistent; their banana trails use the same deferred placement pool. Specialized vine-swing rewards retain their existing event-driven creation and streamer registration.

Validation includes the actual opening, all live-root registrations/materials/mobile shadows, culling after both runners pass 220 m, collected-item reuse, nested hitbox restoration and moving-hazard reset. Thirty-two deterministic seeds passed runway clearance and all-three-gem coverage checks. Counts vary with randomization; one opening layout contained 61 bananas, four coconut pickups, three bombs, three BTM abilities, and 23 obstacle/prop placements. A sampled startup created 39 gameplay instances for roughly 700 full-course placement plans.

The existing mobile audit describes the earlier implementation and measurements. This follow-up replaces its synchronous full-course pickup/obstacle construction with deferred pooled placements. Geometry builders still perform their small fixed amount of bridge/ground setup at scene entry.

The final regression run passed 34 opening/pooling assertions and 32 seeded-layout checks. A 61-window sweep through the finish peaked at 101 live gameplay instances, recorded 536 reuses, and passed 708 bridge-banana height checks. Unity compilation and the full solution `dotnet build` passed with zero errors (existing warnings remain). The scene file's checksum was unchanged, and the user's unsaved Editor scene was preserved.
